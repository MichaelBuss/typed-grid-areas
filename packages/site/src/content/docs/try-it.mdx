## Playground

The two designs from the [Examples](/typed-grid-areas/examples/) page, in a
container you can resize: drag its corner, or the slider. Untick an optional
area to take its slot out, and the grid switches to the
[derived layout](/typed-grid-areas/concepts/areas/) for what's left.

Each grid's [breakpoints](/typed-grid-areas/concepts/breakpoints/) measure
the space the grid itself is given. The ID card switches at `@md` (448px).
The PreferenceCard's content grid switches at `@sm` (384px) of its own
width, so with the input panel present the card switches a little wider.

<Playground client:load />

This demo would look the same in every framework: placement is CSS, and
every adapter writes the same CSS and the same markup. The playground's own
JavaScript only runs its controls and reads out the width; the card in it
measures nothing. Below the card is the CSS the core generated for the
design's definitions, the same CSS whichever adapter renders it.

## In your framework

Each stable adapter has a small example app, built with its framework's
usual tooling and depending on the published packages. Each renders the
PreferenceCard, with its optional areas, its breakpoint and its nested
grid. Open one in StackBlitz, misspell an area where a comment invites you
to, and see the type error in the editor or with `npm run typecheck`.
